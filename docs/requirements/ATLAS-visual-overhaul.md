# ATLAS — Complete Visual Overhaul: Premium UI, Motion Design & Anti-AI-Slop Design Direction

## 1. MAIN OBJECTIVE

The current ATLAS application is functional but visually underdeveloped.

It looks too much like a generic AI-generated MVP rather than a polished fitness application created by an experienced product design team.

**Your task is to perform a comprehensive visual and interaction redesign of the existing application.**

This is not a request to rebuild the architecture, remove existing functionality or generate another collection of generic UI components.

I want a distinctive, premium, modern, highly polished application with an exceptional level of attention to detail.

The intended quality should feel comparable to carefully crafted commercial applications rather than an automatically generated prototype.

Keep the existing modular architecture, database, navigation logic and functionality.

You are allowed to redesign screens, components, layouts, typography, animations, icons, transitions and graphical assets.

**Do not stop after producing design recommendations. Implement the improvements directly in the existing project.**

---

## 2. THE MOST IMPORTANT RULE — NO GENERIC AI-GENERATED UI

Avoid common visual patterns associated with generic AI-produced interfaces.

Specifically, avoid:

- Endless identical rounded rectangles stacked vertically.
- Every card having the same dimensions and visual weight.
- Excessive empty space without purpose.
- Generic dashboard layouts with no personality.
- Random gradients added to everything.
- Unnecessary glowing borders.
- Excessive blue and purple neon effects.
- Inconsistent typography.
- Overly large headings.
- Poorly balanced spacing.
- Emoji used as interface icons.
- Fake statistics and decorative graphs.
- Blank exercise cards.
- Repetitive placeholder illustrations.
- Generic progress bars everywhere.
- Heavy nested cards within other cards.
- Generic motivational quotes taking up valuable screen space.
- Excessive use of glassmorphism without visual hierarchy.
- Huge buttons that make the application feel like a prototype.

Every visual element needs a purpose.

**The application should feel designed, not generated.**

Use a coherent visual language that gives ATLAS its own identity.

---

## 3. VISUAL ART DIRECTION

The visual style should combine:

- Apple's modern interface refinement.
- The clean visual hierarchy of premium fitness applications.
- Sophisticated typography.
- Subtle Liquid Glass effects.
- Editorial-style exercise photography.
- Elegant motion design.
- A touch of futuristic RPG progression aesthetics inspired by the atmosphere of Solo Leveling.

This should result in an original identity, not a direct visual copy of any existing product.

### Design principles

**1. Precision**

Every margin, padding, alignment and component size should feel deliberate.

**2. Visual hierarchy**

Important information must immediately attract attention.

Less important information should remain accessible without competing visually.

**3. Depth**

Use layering, translucency, shadows, highlights and subtle transitions to create spatial depth.

**4. Personality**

ATLAS should have recognizable visual patterns, typography, cards, interactions and animations.

**5. Restraint**

Complexity should come from thoughtful details rather than excessive decoration.

**6. Consistency**

All screens must share one design language.

# 5. REBUILD THE VISUAL HIERARCHY OF EVERY SCREEN

Audit every implemented screen.

Do not merely change colors or border radii.

Reconsider the actual arrangement and presentation of information.

## HOME

The Home screen should feel like a personalized athlete dashboard.

Suggested structure:

### Header

- Small profile avatar.
- Time-sensitive greeting.
- Current date.
- Compact current-level indicator.
- Minimal action icons.

### Main Workout Card

A large, beautifully designed card showing the next workout.

It should contain:

- Workout name.
- Target muscle groups.
- Program name.
- Exercise count.
- Estimated session duration.
- Relevant visual artwork or exercise photography.
- Strong Start Workout action.
- Subtle visual indicator of today's schedule.

This should be the main visual focus of Home.

Avoid putting another five equally important cards above it.

### Below the Main Card

Use a considered editorial layout for:

- Current training split.
- Weekly activity.
- Recent PR.
- Next workout preview.
- XP progress.
- Small training calendar.
- Quick access to recent history.

Use a mixture of compact horizontal cards, full-width panels and visually grouped elements.

Do not make every section look identical.

# 6. EXERCISE PHOTOS AND ANIMATIONS — HIGH PRIORITY

The application must not look like a text-only exercise database.

Implement a proper exercise visual media system.

## Visual direction

Use imagery that is:

- High resolution.
- Consistent in presentation.
- Professionally composed.
- Easy to understand.
- Suitable for dark and light interfaces.
- Clearly connected to the exercise.

Prefer a cohesive visual library rather than dozens of unrelated images with different lighting and backgrounds.

## Exercise Demonstrations

Where assets are available, show a short looping movement demonstration.

Ideal behavior:

- Static thumbnail when not active.
- Smooth transition into demonstration mode.
- Clear movement sequence.
- Video or animation playback where useful.
- Respect reduced-motion preferences.
- Avoid autoplaying large numbers of videos simultaneously.

The user should be able to understand the movement without reading a lengthy explanation.

## Media Sources

Evaluate suitable legally reusable exercise media datasets.

Verify licenses before integrating content.

Do not assume a publicly accessible image or TikTok video can be downloaded and bundled.

For copyrighted creator demonstrations, use permitted links or supported playback methods.

Where media is unavailable, use a visually consistent illustrated placeholder and mark missing assets in the content coverage report.

**Never use unrelated stock photos or fake exercise imagery just to make the interface look populated.**

## Performance

Use efficient image loading, caching and thumbnails.

Evaluate `expo-image` and compatible media libraries.

Do not load full-resolution exercise videos inside scrolling lists.

The exercise library must remain responsive when containing hundreds of entries.

# 7. ADVANCED MOTION DESIGN SYSTEM

The current application has too few animations.

I want the entire experience to feel more alive, fluid and responsive.

However, animations must serve the interface.

Use tasteful microinteractions rather than constant motion everywhere.

## Animation libraries

Prefer:

- React Native Reanimated.
- React Native Gesture Handler.
- Expo Haptics.
- Lottie for appropriate authored animations.
- Rive when complex interactive animations provide clear value.

Verify current Expo compatibility before installation.

Create reusable animation primitives and motion tokens.

## Motion specifications

Use consistent approximate timing ranges:

- Button feedback: 100–160 ms.
- Small state transitions: 160–240 ms.
- Card transitions: 220–320 ms.
- Sheet/modal transitions: 250–400 ms.
- Major completion animations: 500–1000 ms where appropriate.

These are starting points, not rigid values.

Prefer smooth spring motion for interactive elements and appropriate easing for passive transitions.

### Required microinteractions

**Buttons**

- Subtle press scale.
- Controlled spring return.
- Optional haptic feedback.
- Smooth active/disabled state transitions.

**Cards**

- Gentle press response.
- Animated selection states.
- Soft visual transitions when content changes.

**Bottom Navigation**

- Smooth active-indicator movement.
- Subtle icon scaling.
- Soft background highlight transitions.
- Optional haptic feedback.
- Centered Home remains the primary button.

**Menus**

- Smooth expansion and collapsing.
- Small sequential appearance of actions.
- No abrupt content jumps.

**Modals**

- Smooth opening and dismissal.
- Background dimming.
- Appropriate drag-to-close gestures.

**Exercise Sets**

- Completion feedback.
- Checkbox transition.
- Short success effect.
- Progress updates.

**Timers**

- Smooth circular or linear progress.
- Clear completion state.
- Optional gentle vibration.

**XP Progression**

- Animated progress bar.
- Animated numerical XP increments.
- Level-up overlay.
- Rank transition.
- Achievement unlock animation.

**Charts**

- Subtle entrance transitions.
- Smooth data-range switching.
- Interactive tooltips.

**Skeleton Loading**

- Proper loading placeholders.
- No sudden layout shifts.
- Smooth transition into actual content.

## Motion Quality Requirements

Do not animate everything simultaneously.

Avoid distracting bouncing, exaggerated elastic effects or perpetual motion.

Aim for smooth 60 FPS interactions on typical target devices when practical.

Respect reduced-motion accessibility preferences.

Provide reduced-cost animation fallbacks for weaker devices.

Do not let effects delay workout logging.

# 9. MAKE THE INTERFACE FEEL MORE PHYSICAL

The UI should react naturally to the user.

Implement appropriate feedback through:

- Haptics.
- Spring animations.
- Press states.
- Smooth drag interactions.
- Animated bottom sheets.
- Contextual transitions.
- Scroll-aware visual behavior.
- Subtle depth changes.

For example:

When a user holds an exercise card to reorder it:

1. The card slightly increases in apparent elevation.
2. It follows the gesture smoothly.
3. Surrounding entries move naturally.
4. The card settles into its new position.
5. A subtle haptic confirms the action.

This level of attention should extend across the application.
