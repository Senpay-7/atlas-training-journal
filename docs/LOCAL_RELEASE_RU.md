# ATLAS 0.2 — локальная сборка для проверки

## Открыть приложение

В исходной папке `Training App` запустите **Open-ATLAS.cmd**. Адрес: **http://127.0.0.1:8085**. Он сохраняет прежний адрес и локальную историю. Повторный запуск использует уже работающий сервер. Если приложение открыто, обновите страницу после пересборки.

Файл `index.html` нельзя просто открыть через `file://`: SQLite использует WebAssembly, Worker и cross-origin isolation. Веб-экспорт находится в `dist`, готовый комплект — в `releases/atlas-0.2.0/web`. Для другого компьютера скопируйте исходники/комплект и запустите HTTP-сервер с заголовками из `_headers`.

## Что проверить

1. **Профиль → Настройки:** тёмно-синяя, белая и чёрная темы; русский, украинский и английский; уменьшение анимаций.
2. **Планы:** 14 шаблонов. Кнопка **⋯** открывает настройку своей копии. Платные чужие программы не скопированы.
3. **Начать тренировку:** карточки показывают план `3 × 10`. Кнопка записи подхода открывает два поля в отдельном окне. Чип сохранённого подхода позволяет исправить/отменить его. **⋯** меняет план только этой тренировки; через общее меню можно подготовить новую версию сплита.
4. Замена упражнения с сохранёнными подходами и уменьшение числа подходов ниже записанного номера заблокированы. Сначала отмените конкретные записи. Завершённая история не меняется.
5. **Упражнения:** гоблет-присед и сплит-присед имеют AI-черновики из трёх фотографических кадров. При открытии воспроизводится последовательность, доступны пауза и смена кадра. Уменьшение анимаций отключает автозапуск. Это раскадровка для проверки, не плавное видео и не техника, подтверждённая тренером. Отжимания оставлены только в `assets/demos/pushup-review-v2.png`: нижний кадр требует исправления.
6. **Профиль → Аккаунт и облако:** без настройки явно отображается локальный режим. Данные по-прежнему сохраняются в SQLite. Google и почта не имитируются.

## Chrome / Edge

В комплекте папка `extension` и архив `releases/atlas-extension-0.2.0.zip` (если упакован из исходников). Распакуйте архив, откройте `chrome://extensions` или `edge://extensions`, включите режим разработчика, выберите **Загрузить распакованное расширение** и эту папку.

Это **ATLAS Training Companion**: кнопки главной страницы, планов, тренировки и аккаунта открывают сайт в обычной вкладке. Адрес по умолчанию — локальный `http://127.0.0.1:8085`; сперва запустите Open-ATLAS.cmd. После размещения укажите HTTPS-адрес в настройках расширения. Расширение не копирует токены и тренировочную базу, не читает посторонние вкладки и запрашивает только `storage` для собственного адреса и языка. В магазинах расширений оно не опубликовано. Ручная загрузка в настоящий Chrome/Edge требует отдельной проверки.

## Подключение аккаунтов

Выбран **Supabase Auth + Postgres**, **Resend SMTP** для писем, **Cloudflare Workers Static Assets** для сайта. Проекты ещё не созданы. Пошагово: [CLOUD_SETUP_RU.md](./CLOUD_SETUP_RU.md) в исходниках. Экспорт приложения уже содержит необязательный SDK и интерфейс; после заполнения `.env` нужно пересобрать web/native, поскольку Expo подставляет публичные переменные при сборке.

Синхронизация первой версии **ручная**: проверить копию → выбрать направление → подтвердить. Сервер сравнивает revision, хранит 20 последних облачных версий; загрузка на устройство создаёт локальную копию восстановления. Автоматического объединения двух историй нет. Бета-лимит снимка — 500 KB. Токены в экспорт тренировок не входят. Локальная история общая для текущего профиля устройства и остаётся после выхода; при другом аккаунте ничего не отправляется автоматически.

## Android / iOS

Исходники общие с сайтом. `app.json` содержит схему `atlas`, идентификаторы приложения и плагины; `eas.json` — профили preview APK / production. Экспорт JS/Hermes не является APK/AAB/IPA. Подписанных пакетов и проверки на телефоне пока нет. Для выпуска понадобятся выбранные идентификаторы, учётная запись сборки, подпись, настройка deep links/OAuth и тестирование реальных устройств. Не используйте Expo Go для проверки production Google redirect.

## Ограничения перед выпуском

Демонстрации требуют визуального и тренерского одобрения. Облачные письма/Google/две реальные сессии требуют проекта Supabase. Нужны проверка зависимости по актуальному audit, нагрузочные тесты больших историй, миграция с синхронного SQLite Web API при росте, политика конфиденциальности, удаление аккаунта и реальные магазинные проверки. Продуктовый план и гипотезы монетизации — `docs/PLATFORM_AND_PRODUCT_PLAN_RU.md`.
